# Runtime Proxies & Policy Engines: Comparative Benchmark and Gap Analysis

## Executive Summary

As the Model Context Protocol (MCP) and agentic AI ecosystem mature, the necessity for robust security and policy enforcement becomes paramount. `mcp-fingerprints` has established itself as a premier tool for out-of-band structural validation, static analysis, and discovery of MCP servers. However, a distinct category of tools has emerged focusing on *inline, runtime security*: AI gateways, reverse proxies, and policy enforcement engines.

This report provides an in-depth comparative benchmark and gap analysis between `mcp-fingerprints` and prominent runtime security products: Invariant Labs, Lakera Guard, Cisco AI Agent Gateway, and Cloudflare AI Gateway. The objective is to delineate the boundaries of structural validation versus runtime inspection, identify critical capability gaps where `mcp-fingerprints` stops and runtime engines begin, and propose architectural blueprints for non-intrusive integration points.

## Technical Findings by Severity

### 🔴 High Severity Gaps

**1. Lack of Inline JSON-RPC Reverse Proxying**
*   **Context:** `mcp-fingerprints` operates strictly out-of-band. It analyzes source code, probes endpoints for structural compliance, and catalogs metadata.
*   **Gap:** When an LLM client communicates with an MCP server, `mcp-fingerprints` is not in the data path. It cannot intercept, block, or modify malicious requests (e.g., prompt injections passing through to tools) or exfiltrated responses (e.g., sensitive PII returned by a tool). Products like Lakera and Cloudflare AI Gateway thrive precisely by intercepting this traffic.

**2. Absence of Real-Time Payload Inspection (SQLi, SSRF, Bounds)**
*   **Context:** While `mcp-fingerprints` validates that a tool parameter *should* be an integer based on the JSON schema, it does not verify this at runtime.
*   **Gap:** An LLM might hallucinate or be manipulated into passing a malicious string (e.g., `' OR 1=1 --`) to a parameter expected to be a string but used in a database query. Invariant Labs and Cisco actively inspect payloads for injection attacks, SSRF attempts (when URLs are passed to tools), and runtime bounds violations.

### 🟡 Medium Severity Gaps

**1. No Policy Enforcement Engine (RBAC, Identity, OPA)**
*   **Context:** `mcp-fingerprints` describes *what* a server does, but not *who* is allowed to use it or *under what conditions*.
*   **Gap:** In enterprise environments, tool execution must be governed by policies (e.g., "Agent X can read files but not write," or "Only Admin users can trigger the `drop_table` tool"). Cisco and Invariant integrate with RBAC and OPA (Open Policy Agent) to enforce these rules. `mcp-fingerprints` lacks a vocabulary or mechanism for defining or evaluating access control policies.

**2. Dynamic Context Unawareness**
*   **Context:** The catalog generated by `mcp-fingerprints` is static between synchronizations.
*   **Gap:** Runtime proxies can make decisions based on dynamic context: rate limiting, current user session, or accumulated token usage (Cloudflare AI Gateway). `mcp-fingerprints` cannot provide real-time telemetry or enforce quotas.

### 🟢 Low Severity Gaps

**1. Performance & Latency Overheads (Advantage: `mcp-fingerprints`)**
*   **Context:** Because `mcp-fingerprints` is out-of-band, it introduces zero latency to actual LLM-to-Agent/Server communication.
*   **Gap (for competitors):** Inline proxies inherently add a network hop and processing time. For latency-sensitive agentic loops, this can be detrimental. The gap here is that `mcp-fingerprints` does not offer a *fast path* runtime module; it relies entirely on the client to enforce any schemas it discovered.

## Architectural Enhancement Proposals

`mcp-fingerprints` must adhere to its core directive: **pure-structural domain isolation**. It should *not* become a heavyweight runtime proxy or a deep packet inspection firewall. Instead, it should position itself as the *authoritative source of truth* that configures and informs lightweight runtime hooks or external policy engines.

### Blueprint 1: The Sidecar Policy Generator (Integration with OPA/Rego)

Instead of enforcing policies, `mcp-fingerprints` can generate policy configurations based on structural risk profiles.

*   **Mechanism:** When `mcp-fingerprints` catalogs a server, it identifies structural elements (e.g., tools modifying the filesystem, tools accepting raw SQL, tools requiring HTTP access).
*   **Proposal:** Create a new export module (`mcp-fingerprints export-policy --format rego`) that translates the `ServerPackageSpec` into baseline Open Policy Agent (OPA) Rego rules or Envoy WASM configurations.
*   **Example Output:** A Rego policy that denies execution of the `execute_bash` tool unless the request context carries a specific authorization claim, derived purely from the fact that `execute_bash` was statically fingerprinted as a high-risk signature.

### Blueprint 2: Lightweight JSON-RPC Hook Interface (The "Tap")

Provide a lightweight SDK or hook mechanism that existing proxies (or the clients themselves) can use to validate runtime payloads against the *statically fingerprinted* schema.

*   **Mechanism:** Currently, `mcp-fingerprints` validates schemas during out-of-band probing.
*   **Proposal:** Expose a fast, stateless validation function in the Python SDK: `validate_rpc_call(catalog_entry, json_rpc_payload)`. A lightweight reverse proxy (or an AI gateway plugin) can load the `passports.json.gz` into memory and call this function for every request.
*   **Benefit:** The proxy handles the networking, interception, and blocking. `mcp-fingerprints` provides the structural truth (the expected JSON schema of the tool). If the proxy sees a tool call payload that violates the schema cached by `mcp-fingerprints`, it drops it instantly without hitting the actual MCP server.

### Blueprint 3: Header-Based Enforcement Signalling

*   **Mechanism:** AI Gateways (like Cloudflare or Cisco) often route and filter based on HTTP headers or metadata tags.
*   **Proposal:** When launching an MCP server via a gateway using `mcp-fingerprints` data, the discovery tool injects structural metadata headers (e.g., `X-MCP-Capabilities: resources,tools`, `X-MCP-Tool-Count: 5`). The upstream AI gateway uses these static headers to apply coarse-grained routing or blocking policies, bridging the gap between static discovery and runtime enforcement without `mcp-fingerprints` intercepting the traffic itself.

## Conclusion

The gap between `mcp-fingerprints` and runtime proxies is intentional and architectural. `mcp-fingerprints` excels at mapping the territory (structural validation, AST parsing, protocol adherence), while tools like Invariant Labs and Lakera excel at guarding the roads (payload inspection, RBAC, prompt injection filtering). By exposing its deep structural knowledge via policy generators (OPA/Rego exports) and lightweight validation hooks, `mcp-fingerprints` can perfectly complement these runtime engines without compromising its zero-dependency, out-of-band philosophy.
