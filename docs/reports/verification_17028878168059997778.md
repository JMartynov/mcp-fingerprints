## File Changes & Architectural Upgrades

1. **`src/mcp_fingerprints/protocol_validator.py`**:
   - Added `SUPPORTED_PROTOCOL_VERSIONS`, `LATEST_PROTOCOL_VERSION` (`"2026-07-28"`), `LEGACY_PROTOCOL_VERSION` (`"2024-11-05"`).
   - Added builders `build_discover_request(req_id, client_name)` and `build_initialize_request(req_id, protocol_version, client_name)`.
   - Added `is_discover_unsupported_error(msg)` to identify `-32601` (Method not found) and `-32602` (Invalid params) responses.
   - Updated `validate_mcp_handshake()` to support 2-message modern `server/discover` handshakes as well as 3-message legacy `initialize` handshakes.

2. **`src/mcp_fingerprints/detector.py`**:
   - Upgraded `detect_mcp_stdio()` and `detect_mcp_http()` to negotiate `server/discover` first, recording `protocol_version`.
   - On `-32601` / `-32602`, seamlessly falls back to `initialize` and records legacy protocol version.

3. **`src/mcp_fingerprints/prober.py`**:
   - Added `protocol_version: str | None = None` to `ProbeReport`.
   - `McpStdioProber` and `McpHttpProber` send `server/discover` first with `MCP-Protocol-Version: 2026-07-28` header for HTTP.
   - Transparent fallback to `initialize` when legacy error codes are returned.

4. **`src/mcp_fingerprints/runtime_sandbox.py`**:
   - `probe_mcp_server_stdio()` negotiates `server/discover` with dynamic ID mapping and legacy fallback.

5. **`src/mcp_fingerprints/cli.py`**:
   - Enhanced `validate-protocol` command to validate both MCP 2.0 `server/discover` and legacy `initialize` sequences.

6. **`tests/test_prober.py` & `tests/test_runtime_sandbox.py`**:
